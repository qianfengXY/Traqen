# F001 长上传期间的状态观察

报告人：砚砚 / gpt-6-astra。作者实施诊断，不是独立审阅或完整浏览器验收。

## 诊断胶囊

| 栏位 | 记录 |
|---|---|
| 现象 | 真实 HTTP 上传期间服务端 station=6，页面仍显示第 4 站；修复父级刷新后，材料表仍错误显示零条目。首次文件响应前还保留“提交预期清单”提示。 |
| 证据 | `d1f47bb`；隔离 API 3187/PID 9879，启动 03:33:05；Web 3188/PID 11825，启动 03:33:50；目标提交时间 03:33:03，进程均晚于提交。fixture 日志无 PID 字段，PID 命中数为 0，不作为启动时序证据。时间均为 2026-09-07 America/Los_Angeles。 |
| 根因 | `inFlight` 的写命令互斥同时禁止状态轮询；子表仅在 route/cursor 改变时读取一次；传输阶段事件只在首文件成功之后发出，且 UI 节流没有保留阶段切换。 |
| 诊断策略 | 用浏览器 OPFS 的真实目录句柄替代选择器返回值，经过实际扫描、IndexedDB、HTTP 和服务端字节校验；仅延迟 complete-file 请求，不伪造 API 结果。独立 GET 对照服务端站点及 DOM，复查全部活动材料查询。 |
| 超时策略 | 站点观察窗口 6 秒、表格观察窗口 5 秒；释放测试屏障后收束原上传，失败不重复创建任务。 |
| 预警策略 | 禁止用乐观站点或假计数变绿；禁止为了实时刷新取消写互斥、取消旧响应/卸载隔离、重置用户分页或无限堆积 GET。 |
| 用户交互 | 上传时继续只读刷新当前站点及当前清单页；历史冻结包不轮询。首次文件响应前提示已进入上传阶段，已验证计数仍为零。 |
| 验收 | 浏览器站点 RED（服务端 6 / 页面 4）→ GREEN（6/6）；活动材料表 RED（0 条）→ GREEN（4 条）；阶段事件测试 RED（MANIFEST）→ GREEN（UPLOAD）。17 项来源 Web 测试、定向 ES2017 类型检查、零警告 lint 通过。 |

## 修复与保护

- `observeSourceReads` 分离只读查询与写互斥，一次最多一个未完成的轮询；失败可重读，卸载/abort 停止。请求结果继续经过原会话、选择与响应序号保护。
- 当前任务的 `ArtifactTable` 持续读取同一 cursor，不强制回首页；不可变历史查询仍按用户翻页触发。
- 传输在等待首文件之前发出 UPLOAD 事件；跨阶段事件不被 100ms 节流吞掉。计数仍只来自已确认的文件/字节。
- 调度器测试覆盖慢读不堆积、失败后继续只读观察、停止/abort 后不再请求及不抛出旧会话错误。已有不重试写、未确认响应不能显示验证成功的测试保留。

## 浏览器证据与复现

运行真实工作台，先通过部署诊断连接隔离 fixture，再选择其 Workspace 和来源快照入口。目录中建立 3 个文件与一个空子目录。首次采集得到文件 3 / 目录 1 / 34 字节；刷新后仍在第 7 站等待明确确认，未来站不能提前冻结。确认及冻结后能从确切旧包新建版本，冻结不会自动启动 F002。

新版本保留文件并改动一个 13 字节文件；用网络屏障暂缓该 complete-file 请求。服务端此时为 `WAITING_FOR_CLIENT`、station 6。屏障未释放前，页面应在一个轮询周期后显示第 6 站，并显示 4 条材料；释放后进入第 7 站，实际传输 13 字节、无需重复传输 34 字节。测试脚本的断言都读取真实 DOM 与 HTTP 返回，不直接写 React 状态。

本轮 probe 原件与截图保留在本机临时证据目录 `traqen-f001-browser-check.ut3cwp`，失败记录保留在工具调用输出中。该次试点使用 Chromium headless shell 1234、Playwright 1.61.1、PGlite fixture 和私有临时加密内容存储。它不证明原生 OS 目录选择器授权流程、浏览器 100k、Git 浏览器路径、完整异常矩阵、真实 PostgreSQL 部署或灾备。Hub 预览投递为 `unconfirmed/no_matching_client`，未声称面板已打开。Git 总缓存预算与整仓类型错误仍未收束；F001 未完成。
