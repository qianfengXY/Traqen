# F001 通用迁移测试清单未同步

报告人：砚砚 / gpt-6-astra，在完整实现的整仓验收中发现；本记录是作者的实现诊断，不是正式分支审阅结果。

## 诊断胶囊

| 栏位 | 记录 |
|---|---|
| 现象 | 预期整仓测试通过；实际多个存储测试在公共 `migratedDatabase()` 初始化断言失败，尚未进入各自业务断言。 |
| 证据 | `bc03c4ca1235f6423167fcc76ea2b709b25d1ec1`，托管任务 `hold-ball-1788773869297-v3tlm5`，exit 1 / 279 秒。`test/storage-migrations.test.js:36` 的预期仅到 0035，而实际已应用 0036、0037。 |
| 根因 | F001 的 `8c2e262`、`a1292a3` 新增恢复执行与暂存处置迁移，公共测试的显式预期清单未同步。迁移执行器从 SQL 文件加载并成功提交两条迁移，不是 SQL 执行失败。 |
| 诊断策略 | 对照迁移原文、执行器、提交历史；用单个核心迁移测试稳定复现，再只改预期清单。 |
| 超时策略 | 10 分钟不能确认时缩小到单迁移；不重复运行昂贵的 100k 试点寻找无关证据。 |
| 预警策略 | 若出现 SQL 错误或不同失败根因，重新定位，不能用修改预期掩盖它。 |
| 用户交互 | 无产品行为变更；不修改数据库 SQL、备份、恢复或权限契约。 |
| 验收 | 核心迁移测试 RED → GREEN；全量存储及整仓门禁需继续检查，不把单项绿色当成全部通过。 |

## 修复与验证

命令：`node --test --test-name-pattern='core PostgreSQL migration applies once' test/storage-migrations.test.js`。

- RED：1 项失败、exit 1；差异严格为缺少 `0036_f001_renewal_execution` 和 `0037_f001_staging_disposition`。
- 修复：仅向显式预期数组追加这两个 ID。保留顺序与严格等值校验，不将预期改为从同一实际结果派生，不删除迁移或放宽断言。
- GREEN：同一命令 1 项通过、0 失败、exit 0；原有第二次迁移结果 `[]` 与必需表检查继续执行并通过。
- 原托管命令使用 `set -e`，失败后 web 测试、类型检查和 lint 未执行。其输出尾部不能证明没有其他失败项；后续整仓复验需要保留完整日志逐项核对。

本修复不影响已归档的 `bcb21ac` 100k 服务试点。F001 的 Git 缓存总量、浏览器交互和独立审阅仍未完成，不能据此关闭 Feature。
