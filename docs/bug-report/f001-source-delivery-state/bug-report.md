# 来源工作台的正文覆盖与访问失效传播修复

本报告记录作者实现自检中的反例、根因与验证，不是独立 review verdict、Feature 关闭或部署验收。

## 1. 报告人及范围

报告人：搬砖工 / gpt-6.1-sol。依据 F001 当前设计 `d5735830a2da1365c07f230743c47f552c20cf4e` 的 §6–8、§9–10、UX-13–17，在 `feat/f001-complete-delivery`（基线 `489c51fb5005c10b729d5218e2e289d5465e241d`）的隔离自检发现。

只完善既有来源合同的实现：逐项接受、正文可得性、精确材料查阅、访问失效和冻结操作。不修改设计、来源身份、权限目录、生命周期或 F007 工作会话存储。

## 3. 根因与诊断

1. `VERIFIED` 是存储处置。直接以该字段投影内容覆盖，会把已校验的 LFS/submodule 指针误当成取得外部正文。新 `content-state.js` 统一读模型和库存筛选中的正文可得性，不改不可变的存储处置、manifest 或身份。
2. 固定引用只首次读取；材料表的访问失败没有传播到外层。独立入口也仅更新 error，未清除缓存的 overview / frozen。不是来源服务未重启或文案选择器失配：隔离 API 的真实授权变更、403、DOM 和源码分支相互吻合。
3. 冻结 UI 将两个领域步骤暴露成两个用户提交。新 `freezeReviewedCandidate` 保留服务端确认与最终化两个边界，但在同一次显式意图中顺序执行；拒绝确认则不 seal，未知结果仍查询原操作。
4. 材料 inspector 原本是清单内部展示。现在通过 React portal 使用已有右栏；精确路径筛选在服务端分页前执行并绑定 cursor，避免只在当前页寻找或用相似路径替代。

同类审计覆盖固定引用/独立入口两种父读取模型、材料预览/复制、旧响应取消、显式 READ 重试、完整清单/Gap 分母与冻结前后过期检查。

## 4. 修复选择与保留边界

- 逐项接受使用两张 append-only 表；责任人取当前服务端身份，完整集合用 SQL 归并和不可变确认引用闭合，最早绝对期限决定有效期。不将接受时间纳入 Bundle/component 身份。
- 父视图撤权时一起清除受保护读取状态、取消请求及传输；重新读取不授予新权限、不改原引用、不自动选择最新。
- 原文预览最多 64 KiB UTF-8 纯文本，有取消和超时；不执行脚本，不用上传的 PASS 报告证明执行成功。原文复制和引用复制分开并复验当前读取权限。
- 同包历史 Receipt 精确查阅不被最新续签替代；备份 catalogue 包含逐项接受及确认引用，仍按精确 Bundle/Receipt 验证恢复。
- F007 尚无已交付的工作会话关联/结果查询服务。宿主接入面只传受约束引用，未接入时明确不可用；不新增会话 Schema/API 或浏览器权威存储，不用模拟宿主宣称联合验收通过。
