# F008：统一登录与空间权限

> **状态**：spec（设计已确认，尚未实施）| **负责人**：TBD | **优先级**：P2
> **当前阅读入口：** [功能与架构设计 V1.1](../design/F008-unified-login-space-permissions/README.md)。该设计是本 Feature 的权威合同；本页只做聚合与追溯，不另立规则。

## 为什么

Traqen 目前要求在页面里粘贴部署访问令牌，刷新即需重填；所有人共用一个固定身份，工作空间列表不按人过滤，来源快照和业务审核又各有一套凭据。用户的目标体验是“登录 Traqen → 回到上次的工作空间”，同时让每个操作对应真实的人，并按空间授予和撤销权限。

## Current State / 现状基线

- 页面令牌只存在内存，身份固定为 `WEB-OPERATOR`；部署令牌是大多数业务接口的通用凭据。
- 调用者身份（`userId`、`actorId`、租户、principal）由客户端提交，列表不做成员过滤。
- 来源快照使用独立的成员凭据与 READ / MAINTAIN 授权；业务审核由环境变量中的 token 绑定角色。
- 部署经同源网关和 cpolar 隧道公网可达。

代码锚点与核实细节见设计第 1 节。

## 做什么

| 阶段 | 内容 |
|---|---|
| A 身份与权限基础 | 账号、会话、部署终端初始化、网页身份管理、系统管理员两步验证、统一空间授权与全部入口检查、审核角色绑定、程序身份、迁移与受限恢复 |
| B 空间申请与管理 | 建空间申请（系统管理员审批，申请人成为 Owner）、加入空间与角色申请（空间管理者审批）、空间目录与可见性、成员管理、待办与通知 |

两段都完成并通过整体验收，F008 才算完成；多人访问只在全部入口完成权限检查之后开放。

## 已确认的关键决定

- 首位系统管理员在部署终端初始化；之后系统管理员可在网页添加其他系统管理员，并须启用两步验证（D2）。
- 账号由系统管理员开通，不开放注册，开通不附带空间权限（D1）。
- 密码至少 8 个字符，不要求定期更换（设计第 7.3 节）。
- 任何账号都能申请创建空间，经系统管理员批准后成为 Owner；Owner 管理本空间其他角色并可指定权限管理员。
- 系统管理员可以操作所有空间，日常事务默认交给空间管理者。
- 审核角色为角色集合，同一空间内业务组与合规组互斥（D3）。
- F006 的能力继承与 Agent 授权规则不变。
