# 本地 Workspace 分析与功能树

## 实现愿景

用户可以自定义 Workspace、选择一个代码工程，在不上传源码的前提下自行分析，查看有证据支撑的当前能力形成的功能树，并对每一个功能查看五段式追溯。分析发现不能静默地把实现观察晋升为已确认的业务真相。服务端架构与保留权威的增量规则见[分析 Agent 设计](analysis-agent-design.zh-CN.md)。

## 用户流程

1. 输入 Workspace 名称与稳定的 Project ID。
2. 通过浏览器目录选择器选择本地代码工程。
3. Traqen 在本机读取受支持的文本文件；原始源码既不上传也不持久化，仅把有界的派生索引保存到浏览器 IndexedDB。
4. 本地确定性分析 Agent 发现 Spring MVC/WebFlux 和 JAX-RS 接口、Java 后端组件与接口方法、HTTP 路由、OpenAPI JSON 操作、公开且可调用的 JavaScript/TypeScript 能力和 `package.json` 命令。
5. 同一次分析投影为两个互斥的功能树模式。**纯业务功能**过滤 HTTP 接口、命令、Repository、Adapter、Interface、Utils 和配置支持代码；**API 接口**只包含发现的 HTTP/OpenAPI 操作，并展示协议、方法、路径、处理入口和匹配实现代码块。切换模式不会重新分析，也不会重复保存记录。
6. 在任一模式内，结果按照“Workspace → 可读模块 → 业务领域或产品区域 → 发现分组 → 候选 Feature”组织成功能树。父节点数字始终表示当前模式下的下级功能总数，而不是直接文件夹数或未过滤的扫描总数。
7. Workspace 分析首先展示当前功能树模式的项目全局统计。选择 Workspace、模块、领域/产品区域、发现类型或功能任意节点后，使用相同口径重新统计该节点及其全部下级。
8. 功能追溯继续承担详情查看：点击候选功能后，展示功能描述、设计源码、配置线索、关联测试、测试结果、独立可信维度和 TraceGap 责任归属。Workspace 分析、功能追溯和追溯图谱共享同一个全局树模式与选择状态。

## 分层分析统计

- 统计包含功能点数、已定位的设计实现、去重后的模块相关或项目全局配置线索、去重后的关联测试用例和执行结果分布。
- 治理统计分别展示待人工确认、实现待审核、冲突和明确不符合，不能相互替代。
- 证据统计展示完整链、不完整链、阻断级 TraceGap 和警告级 TraceGap，不生成综合绿色分数。
- `PARTIAL`、`UNKNOWN` 和 `NOT_RUN` 表示缺失或尚未核验，不属于不符合。“不符合”只统计显式不符合状态、失败/错误执行或对应的违规 Gap；冲突继续单独统计。
- 下一层统计表对当前节点的每个直接子节点重复上述口径，可以从 Workspace 逐层下钻到模块、领域/产品区域、发现类型和单个功能，同时不会混入其他项目数据。

## Workspace 生命周期与全局导航

- 本机尚无项目时，Workspace 路由只展示聚焦的初始化引导页。在创建项目身份之前，不挂载分析表单、Agent 会话、功能树和统计信息。
- Workspace 创建入口是标题旁紧凑的 `+` 按钮，创建过程进入仅属于 Workspace 路由的独立页面状态。创建期间不挂载当前项目的分析页面；只有创建完成或用户取消后才恢复分析内容。切换到任何其他产品页面都会结束创建状态，创建内容不会泄漏到其他页面。
- 左侧 Workspace 切换器可以创建并保留多个本地项目。选择项目后，该项目成为所有产品页面的当前数据边界。
- 第一次扫描用于初始化项目；它不是仅属于“Workspace 分析”页面的一份孤立报告。
- 后续对同一根目录分析时，按相对路径、文件字节数、最后修改时间和扫描器版本比较。未变化文件直接复用扫描记录；新增或修改的受支持文件才重新读取；已删除路径先移除，再重建功能树。扫描器升级后，旧记录会自动失效并重新分析。
- 浏览器会在若干有界文件批次后以及收到暂停请求时写入活动运行检查点。如果页面、浏览器或机器中断作业，重新选择同一目录后会复用兼容的已完成文件记录，不重新读取已完成工作。紧凑的完成结果摘要独立保留，供后续历史查询栏目使用。
- 初始化后的 Workspace 名称、Project ID、功能树、当前功能、当前追溯块和树展开状态由产品级会话统一持有，在各产品页面之间切换时不会丢失。
- “功能追溯”直接复用初始化得到的功能树。点击任一功能即可查看该候选的五段追溯链，不需要重新扫描。
- “Workspace 分析”保留为初始化和重新扫描入口；“功能追溯”是逐项审核候选功能的主要工作界面。
- 连接 API 后可以临时查看服务端派生的 Feature；返回自 Workspace 时恢复本地初始化的功能树和选择位置。
- “功能追溯”和“追溯图谱”都使用当前项目的功能树与当前功能；本地项目生效时不会回退到其他 Workspace 数据。
- 纯业务功能/API 接口模式在 Workspace 分析、功能追溯和追溯图谱之间全局一致；切换后只有当原选择不属于新模式时，才自动选择新模式的第一个候选。
- 项目摘要和派生分析记录在同一浏览器配置中完整刷新后仍然存在。目录 `File` 句柄不会保留，因此执行增量分析或续跑前需要重新选择原工程根目录。
- 分析 Agent 与产品其余部分统一使用全局主题变量和响应式桌面布局。宽屏下使用完整可用内容宽度和紧凑外边距，不再受居中的 1920 像素上限影响。主 Agent 与子 Agent 对话在固定高度的区域内滚动，不再形成无限延伸的黑色终端页面。

## 可信边界

- 扫描发现项是实现候选，不是规范性 Feature。
- 在授权人员确认业务说明、权限、前置条件、依赖、适用范围和例外前，业务权威保持 `PENDING`。
- 在实现映射经过审核前，源码到 Feature 的符合性保持 `PARTIAL`。
- 关联测试文件只是线索，不是已批准 TestSpec。关联必须来自同一模块内完全匹配的测试/源码文件名或可调用符号名；通用词重合不能作为覆盖证据。
- 扫描不会执行工程代码。在可信 Runner 针对所选 Snapshot 和部署回传签名 Evidence 前，验证结果保持 `NOT_RUN`。
- 缺少业务权威、实现审核、TestSpec 或当前执行时，必须保留明确的阻断级 TraceGap。

## 本地安全限制

- 忽略依赖、版本控制、构建产物、覆盖率和 vendor 目录。
- 对受支持文件进行有界分批处理，不设置工程级文件数量或总字节上限，使十万级文件工程不再因人为上限而必须拆分扫描。
- 只持久化文件元数据、已发现的功能索引、有界源码/测试片段和脱敏配置线索，不保留完整源码树。持久化快照只保存一份扫描记录，加载时重新构建聚合分析。
- 单个受支持文本文件最多读取 768 KB。
- 功能树按需展开，未打开的模块和发现类型不会一次性在页面中创建全部叶子节点。
- 排除真实 `.env` 变体，仅允许环境模板，并在展示前脱敏配置中的疑似密钥值。
- 不向托管的 Traqen 站点上传源码；不持久化完整源码文件、真实 `.env` 值或未脱敏的疑似密钥配置。

## 当前发现范围

扫描器识别 Spring `@RequestMapping` 和各 HTTP 方法映射，并合并类级与方法级路径；识别 JAX-RS `@Path` 与 HTTP 注解；识别 Java Controller、Service、Repository、Component、定时任务、消息/事件监听方法、接口方法以及有意义的公开/受保护后端方法；关联 Maven/Gradle、application 配置线索和 Java 测试源码。普通 getter/setter 与配置工厂方法不会再被提升为功能。接口叶子优先使用 Java 方法名、路由处理器名或 OpenAPI 的 summary/operationId 作为可读名称，同时保留 HTTP 方法和路径作为技术明细；匿名 `async` 处理器绝不能形成误导性的 `Async` 名称。同时继续识别 JavaScript/TypeScript 导出函数、类与可调用变量、公开 Python 函数、C# 公共方法、Go 导出函数、Rust 公共函数、HTTP 路由注册、OpenAPI JSON 路径和 npm scripts。普通常量和 Schema 不会仅因被导出而晋升为功能。测试、Mock、fixture、sample 和 story 只提供辅助证据，不形成 Feature 候选。配置线索仅来自配置形态文件，排除测试 fixture 与 package manifest，并按模块/领域邻近关系保守关联。Java 生成目录 `target`、`out` 与 Gradle 缓存仍会被排除。

工程/运行命令仍保留在底层扫描清单与统计模型中，但有意不进入两个面向用户的功能树模式，避免工程操作伪装成纯业务功能或 API 接口。

针对真实仓库 `zts212653/clowder-ai` 的验证记录见 [Clowder AI Workspace 扫描验证](../implementation/clowder-ai-workspace-analysis-2026-07-18.zh-CN.md)。其中发现的数千项是实现候选，不能解释为该仓库已经拥有同等数量的已确认业务 Feature。
