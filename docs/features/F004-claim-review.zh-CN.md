# F004 — 测试/执行证据、变更影响与重验证

**状态：** Spec
**负责人：** TBD
**依赖：** F001、F002、F003

## 为什么

理解存量系统的价值，在于让下一次变更更安全。但代码到测试资产的链接并不能证明该测试运行过、通过过，或覆盖了变更行为。影响分析必须区分结构性证据、已审阅语义主张、执行结果和未知覆盖范围，使团队能够作出知情决策，而不会被虚假的“无影响”结论误导。

## 目标结果

F004 记录快照绑定的测试与执行证据，针对声明的变更比较证据图谱，并给出建议性的重验证指引。结果分类为 `CONFIRMED`、`POSSIBLE` 或 `UNKNOWN`，每种分类都带有准确的证据和覆盖边界。

首个版本仅提供决策支持：不会自动合并、部署或阻止工作。

## 范围

### 包含

- 区分测试资产、声明测试用例与实际执行的测试运行。
- `TestExecution` 来源信息：运行器、环境、命令或工作流、结果、相关日志/产物、源码快照和执行时间。
- 两个源码快照之间的版本化 `ChangeSet` 比较。
- 跨代码、配置、API、已审阅业务主张、测试资产和真实执行证据的建议性影响路径。
- 带分类、理由、证据链接和已声明覆盖缺口的重验证建议。
- 变更审阅视图，同时展示变更影响到的业务功能和 API 两个投影。

### 不包含

- 根据静态测试引用就宣称测试已经通过。
- 在存在缺口、不支持提取器、未观测运行时行为或过期执行记录时宣称“无影响”。
- 在首个版本中实施强制 CI、合并、发布或生产阻断。

## 影响语义

| 分类 | 含义 |
| --- | --- |
| `CONFIRMED` | 快照绑定的证据已建立关系或执行结果。 |
| `POSSIBLE` | 可追溯路径或已审阅主张提示存在关系，但证据不完整。 |
| `UNKNOWN` | 已声明缺口、过期运行、不支持行为或缺证据阻止有边界的结论。 |

空的影响列表不是通过结果。它必须写出能证明该结论的覆盖证明；否则结果为 `UNKNOWN`。

## 用户旅程

1. 工程师为拟议或已完成的变更选择变更前、后的源码快照。
2. Traqen 识别变更产物，并遍历确定性事实、已审阅主张和可用执行证据。
3. 工程师看到受影响的业务功能和 API、建议重验证项及明确未知项。
4. 工程师登记或关联新的执行证据；下一次分析仍绑定其准确快照和运行上下文。

## 验收标准

- [ ] 未提供运行器、环境、结果、时间戳和源码快照来源信息时，不能创建测试执行记录。
- [ ] 参考试点变更会生成 `ChangeSet`，并在存在时展示到受影响 API 和业务树投影的直接证据路径。
- [ ] 每个重验证建议均包含分类、理由、证据链接和覆盖状态。
- [ ] 静态测试引用与已执行测试结果在界面上明显区分。
- [ ] 缺少运行时观测、不支持分析或运行记录过期时，给出 `UNKNOWN` 而非“无影响”。
- [ ] 初始工作流只给建议，不包含自动合并、部署或 CI 阻断动作。

## 待确认问题

- 当测试执行早于被比较源码快照时，采用什么过期策略？
- 首批集成接入哪些 CI 系统和测试报告格式？
- 在证据质量被验证后，哪些有限策略（如有）可以选择启用强制？

## 依赖与交接

F004 消费 F001 源码身份、F002 事实/缺口和 F003 已审阅主张。它增加执行真相，但不会把执行真相和静态分析混为一谈。任何让影响结果具有强制力的提议之前，都必须通过参考试点证明建议有明确边界。
