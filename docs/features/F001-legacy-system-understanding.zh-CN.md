# F001 — 工作空间与源码真相

**状态：** Spec
**负责人：** CodeX
**关联：** F006 工作空间能力配置

## 为什么

在理解存量系统之前，必须先精确回答一个更基本的问题：我们究竟分析了哪一份、哪个版本的源码？目录名、会持续变化的 checkout 或聊天附件都不足以构成证据。后续每个结论都必须能回指到稳定、受权限约束的源码边界。

## 目标结果

F001 建立只读分析工作空间、不可变 `SourceSnapshot` 与完整 `ArtifactInventory`。清单覆盖文档、代码、测试、配置及其他已发现产物；被排除、不支持、无法读取、已脱敏或扫描失败的材料也必须有明确处置记录。

本功能不推断业务含义、不裁决归属、不发布业务树，也不宣称变更影响；这些由后续功能负责。

## 用户旅程

1. 架构师登记源码根目录及其允许的分析策略。
2. Traqen 捕获不可变快照身份，并清点全部可发现产物。
3. 架构师可以查看哪些材料被分析、哪些被有意排除，以及原因。
4. 后续事实、候选、主张和执行记录都引用该快照，而不是语义模糊的实时文件系统。

## 范围

### 包含

- 带源码定位、访问策略与来源信息的工作空间登记。
- 不可变快照身份：可得时的源码版本、内容摘要、捕获时间和扫描器版本。
- 产物清单记录：路径、类型、内容摘要、大小和处置状态。
- 明确的覆盖状态：`INCLUDED`、`EXCLUDED`、`UNSUPPORTED`、`FAILED`、`REDACTED`。
- 源码访问边界：原始内容只能由获批准的本地提取器，或由显式授权的 F006 Agent 配置读取；禁止未经授权向外部模型传出内容。

### 不包含

- 提取事实或构建 API 树（F002）。
- LLM 语义理解、人工审阅或业务功能树（F003）。
- 测试执行证据、影响分析和重验证建议（F004）。
- 作为生产发布或 CI 卡点。

## 必需记录

| 记录 | 最低字段 |
| --- | --- |
| `Workspace` | 工作空间 ID、已登记源码定位、访问策略、负责人 |
| `SourceSnapshot` | 快照 ID、可得时的源码版本、内容摘要、捕获时间、扫描器版本 |
| `ArtifactInventoryItem` | 快照 ID、产物定位、类型、摘要、处置状态、处置原因 |
| `CoverageGap` | 受影响范围、原因、发现方式、跟进状态 |

无法读取的文件不能静默消失：它必须产生清单处置记录，并在限制分析时产生 `CoverageGap`。

## 验收标准

- [ ] 可登记一个参考仓库，且不会修改其源码。
- [ ] 对相同内容重复清点时，产生相同快照身份和产物摘要。
- [ ] 每个已发现产物恰好有一个处置状态。
- [ ] 被排除、不支持、已脱敏或失败的产物会连同原因对用户可见。
- [ ] 任一后续记录均可写出准确的 `SourceSnapshot` 与产物定位。
- [ ] 参考试点报告在启用语义分析前证明源码边界和清单覆盖情况。

## 待确认问题

- 首批生产适配器支持哪些版本控制系统与归档格式？
- 对含凭据或受监管数据的仓库，获批准的脱敏契约是什么？
- F006 的哪些配置形式可视为对远程分析 Agent 的显式授权？

## 依赖与交接

F001 是 F002–F004 的证据边界。F006 提供可复用的工作空间与 Agent 能力配置；F001 的本地清点可独立验证，但任何远程 Agent 访问都必须使用获批准的 F006 配置。
