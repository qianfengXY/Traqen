# F001 — 工作空间与源码真相

**状态：** Spec
**负责人：** CodeX
**关联：** F006 工作空间能力配置

## 为什么

Traqen 在解释存量系统之前，必须证明它究竟检查了哪一份源码，以及哪些内容没有取得。分支名、实时 checkout 或“扫描成功”都不是证据。F001 将源码边界做成可重放、可见的事实，使 F002–F004 不能在输入不完整时把结论呈现为完整事实。

## 当前状态

此前 F001 基线已提出不可变快照、产物清单与明确处置状态，但首期来源类型、范围控制、Gap 权限、就绪状态和下游准入尚未收敛。co-creator 已在 [2026-08-30 收敛记录](../../feature-discussions/2026-08-30-F001-workspace-source-truth/README.zh-CN.md)确认这些产品选择。

## 目标结果

F001 为一个 Workspace 中的一个 Git 仓库、一个已提交版本建立只读源码底座。架构师登记只读授权的来源，选择 branch、tag 或 commit；Traqen 必须在采集前把它解析为精确 commit。默认范围是整个已提交仓库，也可选择一个明确目录根；范围不是文件类型选择器，也不是规则语言。

密封的 `SourceSnapshot` 包含 `ArtifactInventory`、明确的 `CoverageGap` 与 `SourceTruthReceipt`。重新采集产生新快照，绝不重写旧快照。采集不运行仓库脚本、hook、构建、依赖安装或不受信任 filter，敏感原文不会绕过获批准访问控制。

凭据状态为 `READY`、`READY_WITH_ACCEPTED_GAPS` 或 `BLOCKED`。没有 Gap 的快照可自动成为 `READY`；只有非阻断 Gap 的快照必须先获得人工记录接受，才可成为 `READY_WITH_ACCEPTED_GAPS`；阻断条件不能被接受操作绕过。F002 只能消费合格 Receipt 及其快照，不能以文件路径、branch 名、脏工作区或未完成快照替代输入。

本功能不推断业务含义、不解析 API、不运行测试，也不宣称变更影响；这些由后续功能负责。

## 用户旅程

1. 架构师创建或打开 Workspace，选择已获只读授权的 Git 仓库与 branch、tag 或 commit；Traqen 展示最终锁定的 commit。
2. 架构师保持默认全仓库范围，或选择一个目录根。
3. Traqen 自动预检来源身份、读权限、版本、边界、外部内容和采集安全；以“可开始 / 可开始但预计有 Gap / 必须阻断”及可行动原因呈现结果。
4. Traqen 捕获不可变快照，并为声明范围内每个已发现条目记账。
5. 架构师审阅 Source Coverage：已采集材料、策略隔离、脱敏、不可得外部材料、失败和 Gap。
6. 若只剩非阻断 Gap，架构师记录责任人、理由和有效期；阻断条件必须先解决。
7. F002 接收合格快照 ID 及继承 Gap，而不是可变来源引用。

## 范围

### 包含

- 每份快照对应一个 Workspace、一个只读授权的 Git 仓库和一个精确已提交版本。
- 自动来源预检：来源身份、读权限、版本解析、范围边界、外部内容边界与采集安全。
- 不可变快照身份：仓库身份、精确 commit、声明范围、内容/完整性摘要、采集时间和扫描器版本。
- 产物清单记录：路径、类型、大小、安全取得内容时的摘要、唯一处置与处置原因。
- 已采集、策略隔离、脱敏、不可得、不可读、失败和范围外材料的明确覆盖状态。
- 默认全仓库、可选单一目录根；目录根凭据必须可见地说明仓库其余部分范围外。
- 非阻断 Gap 的责任人、理由、有效期、接受记录和下游继承。
- 手动重采与历史；新版本必定产生新快照。

### 不包含

- 任意路径、非 Git 归档、未提交或脏工作区、多仓库聚合、多目录根和持续监听。
- 用户自定义 glob/regex、“只采代码”等材料类别开关，或用户控制安全、完整性和 Gap 严重度规则。
- 提取事实或构建 API 树（F002）；LLM 语义理解、人工审阅或业务功能树（F003）；测试执行证据、影响分析和重验证建议（F004）。
- 仓库脚本执行、构建、依赖安装、源码修改、CI 卡点和生产部署约束。

## 必需记录

| 记录 | 最低字段 |
| --- | --- |
| `Workspace` | 工作空间 ID、已获只读授权的来源登记、负责人，以及快照、覆盖、历史和权限的隔离 |
| `SourceSnapshot` | 快照 ID、仓库身份、精确 commit、声明范围、完整性身份、采集时间和扫描器/策略版本 |
| `ArtifactInventoryItem` | 快照 ID、产物定位、类型、大小、安全取得内容时的摘要、处置状态和处置原因 |
| `CoverageGap` | 受影响范围、严重度、原因、下游后果和跟进状态 |
| `GapAcceptance` | 非阻断 Gap ID、责任人、理由、有效期和不可变接受记录 |
| `SourceTruthReceipt` | 分开呈现来源身份、范围、完整性、覆盖、Gap、接受和 `READY` / `READY_WITH_ACCEPTED_GAPS` / `BLOCKED` 可消费状态 |

无法读取的文件不能静默消失：它必须产生清单处置记录，并在限制分析时产生 `CoverageGap`。内容摘要只在内容被安全取得时存在。阻断条件包括无法确认仓库或版本身份、来源边界不可访问或不可信、完整性校验失败、路径逃逸、策略冲突及疑似篡改；它们不能由 Gap 接受操作覆盖。

## 验收标准

- [ ] **AC-A1：** 可只读登记一个受控 Git 仓库，且在采集前把所选 branch 或 tag 解析为精确 commit。
- [ ] **AC-A2：** MVP 范围只有全仓库和单一目录根；目录根凭据必须可见地说明仓库其余材料范围外。
- [ ] **AC-A3：** 对相同仓库 commit、范围和采集策略的两次采集产生相同快照身份与清单完整性结果；之后 branch 移动不改变旧快照。
- [ ] **AC-A4：** 声明范围内每个已发现条目恰有一个处置与原因；不可读、脱敏、排除、不可得或失败材料不能静默丢失。
- [ ] **AC-A5：** 采集不执行仓库提供的代码，敏感原文不经 Receipt、清单、UI 或诊断输出泄露。
- [ ] **AC-A6：** 非阻断 Gap 在有记录的接受后仍可见并被下游继承；阻断条件不能通过接受变为可消费。
- [ ] **AC-A7：** F002 只接受 `READY` 或 `READY_WITH_ACCEPTED_GAPS` 快照，拒绝直接来源路径、branch 名、脏工作区、`BLOCKED` 或未完成快照。
- [ ] **AC-A8：** 参考试点证明可重放、显式覆盖、非阻断 Gap 继承，以及无法签发可消费凭据的阻断路径。

## 参考试点

试点使用一个受控 Git 参考仓库，其中有两个 commit 和一个命名的服务目录。Commit A 含代码、文档、配置、测试、安全处理的敏感 fixture，以及一个故意不可得的非阻断外部条目。Commit B 引入路径逃逸或完整性异常。

试点以服务目录作为唯一根采集 Commit A，证明仓库其他材料明确显示为范围外；以理由和有效期接受非阻断 Gap，并证明 F002 只能消费产生的 Receipt。重放 Commit A 得到相同来源结果；所选 branch 后续移动不影响它。采集 Commit B 必为 `BLOCKED`，不能签发可消费 Receipt。

## 待确认问题

产品边界层面没有待确认问题。连接器和存储实现属于实施规划，且不得弱化本合同。

## 依赖与交接

F001 是 F002–F004 的证据边界。F006 提供关联的 Workspace 能力设置；F001 的源码采集不运行 Agent。F002 只消费合格 F001 Receipt、不可变快照、完整清单及其继承 Gap。
