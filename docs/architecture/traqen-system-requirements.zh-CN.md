# Traqen 系统需求：基于证据的存量系统理解

## 1. 使命

Traqen 必须让负责的架构师能够从可得的文档、代码、测试、配置和执行证据中理解存量系统；保存每个结论是如何得出的；并用这种理解让下一次变更更安全。

系统答案的可信程度，取决于其源码版本、证据、权威、不确定性和覆盖范围是否可见。

## 2. 核心需求

### R1 — 版本化源码真相

系统应在显式访问策略下登记源码，并在分析前创建不可变源码快照。每个已发现产物均应清点并赋予一个明确处置状态，包括被排除、不支持、无法读取、已脱敏或失败的材料。

### R2 — 可复现技术证据

系统只能通过版本化提取器生成确定性事实，并应保留源码位置、推导和可复现数据。无法建立事实或关系时，应记录覆盖缺口。

### R3 — 分离 API 与业务权威

系统应在可得时基于确定性的端点/操作/处理器/契约证据发布 API 结构树；只基于人工审阅后的主张发布业务功能树。任何树都不得静默吸收由低权限层级创建的断言。

### R4 — 有边界的 Agent 推理

系统可以使用一个或多个分析 Agent 创建语义候选，但每个候选均应保留运行来源、源码/证据边界、不确定性和审阅状态。模型一致性、置信度或多数计数不得将候选提升为主张。

### R5 — 人工发布决策

系统应支持批准、拒绝、请求补充证据、替代和标记候选过期的审阅决策。被拒绝、替代或过期的候选应保持可审计，但不得显示为当前业务真相。

### R6 — 执行不是源码引用

系统应区分静态测试资产、测试规格和实际测试执行。执行记录至少应标识源码快照、运行器、环境、时间、结果和关联运行证据。静态引用不得显示为已通过的执行。

### R7 — 有边界的影响指引

对于两个源码快照之间声明的变更，系统应通过确定性事实、已审阅主张和执行证据生成建议性路径。每项发现均应为 `CONFIRMED`、`POSSIBLE` 或 `UNKNOWN`，并带有快照绑定的支撑和覆盖限制。只有存在相关覆盖证明时才可陈述无影响；否则结果为 `UNKNOWN`。

### R8 — 安全的源码处理

除非 F006 配置显式授权参与者和出站路径，原始源码内容必须留在工作空间访问边界内。系统应保存管理某次 Agent 或提取器运行的策略和保留上下文。

### R9 — 不隐藏强制动作

初始影响工作流只能提供建议；不得自动阻断 CI、合并、发布、部署或生产数据操作。

## 3. 必需信息模型

| 记录 | 必需来源信息 |
| --- | --- |
| `Workspace` | 已登记源码定位、访问策略、责任负责人 |
| `SourceSnapshot` | 不可变 ID、可得时的源码版本、内容摘要、捕获时间、扫描器版本 |
| `ArtifactInventoryItem` | 快照、产物定位、类型、摘要、处置状态和原因 |
| `Fact` / `EvidenceLink` | 快照、源码范围、提取器推导、可复现令牌 |
| `Candidate` | Agent/运行身份、证据边界、假设、不确定性、审阅状态 |
| `Claim` | 审阅决策、审阅者权限、关联候选和证据 |
| `TestExecution` | 快照、运行器、环境、时间、结果、运行证据 |
| `ChangeSet` / 影响发现 | 被比较快照、分类、路径、缺口、建议 |
| `CoverageGap` | 受影响范围、已发现限制、跟进状态 |

所有记录都必须仅追加或带版本。校正应创建新的推导、决策或修订，而不是擦除旧依据。

## 4. 面向用户的行为

架构师必须能够：

1. 登记源码并准确查看哪些材料被或未被分析；
2. 查看 API 树，并将每个展示的结构节点追溯到源码证据；
3. 运行获批准的分析 Agent，并在不丢失独立输出的前提下比较候选；
4. 在候选成为业务真相前审阅它；
5. 查看业务树及其主张、API、代码、文档、测试、配置和已知缺口；以及
6. 比较两个快照，获得明确的重验证建议，而非没有支撑的保证。

## 5. 质量约束

- **可追溯性：** 已发布节点、边、建议或执行结果必须关联其快照绑定来源。
- **可复现性：** 相同确定性输入和提取器版本必须产生相同事实，或产生显式的确定性失败/缺口。
- **不完整性的诚实性：** 未知、排除、不支持、过期和失败区域必须在树和影响视图中保持可见。
- **可审阅性：** 人工审阅者可复现每条业务主张的证据路径。
- **安全性：** 含密钥或受监管的源码材料不得通过未获批准的提示词、日志、导出或集成离开工作空间边界。
- **可逆性：** 初始建议仅用于决策支持；F001–F004 验收范围不含自动不可逆动作。

## 6. 交付顺序

1. **F006 与 F001：** 能力隔离，以及不可变源码快照和清单。
2. **F002：** 确定性事实、证据链接、缺口和 API 结构投影。
3. **F003：** 获授权 Agent 候选、人工审阅和业务功能投影。
4. **F004：** 执行来源信息、快照比较、建议性影响和重验证。
5. **参考试点：** 在扩展适配器或考虑强制之前，用受控仓库变更验证端到端切片。

## 7. 验收状态

本文已**批准作为 F001–F004 的设计基线**。它不代表已签入实现已经满足这些需求。F006 保留独立实施轨道，不受本次重构替代。
