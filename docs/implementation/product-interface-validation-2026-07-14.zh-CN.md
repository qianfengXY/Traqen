# 产品接口验证 — 2026-07-14

## 结果

该切片将现有协议和 APIs 转变为设计愿景描述的面向用户的产品。它关闭 MVP 验收项目 5、12、13、14 和 15 的显示部分，公开项目 6 所需的人工审核工作流程，并提供 MVP 范围所需的历史 Snapshot 比较。

北极星问题仍然存在：**为什么所选的 Feature 在所选部署上可信？** 该界面不会用综合分数取代独立权威、一致性、验证、新鲜度和冲突维度。

## 产品表面

`web/` 中的响应式 React 工作台提供了三个连接的表面：

1. **Feature 可追溯性** — 五段式“功能描述 → 设计实现 → 配置 → 测试用例 → 测试结果”投影。选择任一块即可查看对应的业务逻辑、设计与代码、配置、TestSpec/断言或执行/Evidence 数据，同时在下层保留有序的 Claim → Scope → Decision → Fact → TestSpec → 断言 → 执行 → Evidence 记录、来源、独立可信维度和显式 TraceGap 所有权。
2. **语句审查** — 可以从 API 加载反向运行和候选。审阅者必须明确提供规范性声明、Scope、目标 ID、基本原理和已确认的冲突。正式决定将发送到经过身份验证的候选人审核端点。浏览器永远不会接受审阅者的身份和角色；其审阅者持有者令牌仅保存在组件内存中，并在成功后清除。
3. **更改影响** — 通过 ChangeSet 端点比较两个不可变的 Snapshot 清单 ID。 UI 显示已更改的 Facts、受影响的 Features/Claims/TestSpecs、无效的派生层、保留的规范事实和历史、语义连续性、警告以及服务器建议的修复顺序。

五段式追溯投影现在采用专门的详情视图。功能描述展示完整的受治理文档和独立可编辑的确认草稿；设计实现展示设计流程、关键决策和具体源代码块；配置展示 DEV/SIT/UAT/PROD 矩阵；测试用例展示策略与可展开的版本化用例逻辑；测试结果按场景组织执行，并允许从失败条目下钻到 TestSpec、失败步骤、期望/实际值、错误和 Evidence。历史失败继续保留，但与当前结果明确区分。

测试数据同时预留 `traqen.testspec.agent/v1` 执行边界，记录派发已批准 TestSpec 以及接收结构化步骤/断言结果、签名 Evidence、Runner 身份和证明所需的字段。本切片有意不接入外部 Agent 执行；只有服务端有权校验回传并派生最终可信状态。

## 真理边界

内置订单提交场景标记为 `DEMO SNAPSHOT`。它的审查行动从来不会坚持任何事情。实时 Feature 可追溯性、候选者审核和历史比较使用 Traqen API 并单独标记。

浏览器不会从部分数据推断绿色状态。实时完整性、维度、分段、间隙、影响、失效和连续性都来自服务器衍生的合约。缺少的必要链接仍然是可见的 TraceGap 并阻止链被表示为完整。

## 浏览器到 API 边界

API 接受显式 `CORS_ALLOWED_ORIGINS` 允许列表。在服务器构建期间会拒绝通配符、包含路径的源以及带有凭据的源。未知来源不会获得访问权限；允许的来源仅接收产品所需的方法和标头。连接面板仅将全局生产 API 令牌保留在页面内存中，并将其发送到 `x-traqen-api-token` 中，因此审核路由可以独立为审核者或实施审核者凭证保留 `Authorization` 。

## 场景已验证

- 完整的当前部署链显示所有必需的阶段和经过验证的 HTTP、数据库、断言、生命周期、LOG 和 TRACE Evidence。
- 语义更改的实现保留规范的 Claim、Scope、Decision 和历史 Evidence，同时仅将实现派生的段和验证段标记为过时。
- 更改后的场景解释了为什么新部署尚不可信，并将每个差距分配给修复角色。
- 演示决策仍然是非持久性的。
- 实时审核在没有审核者凭据的情况下会失败关闭，并将参与者身份留给服务器。
- 历史比较作为命名的 ChangeSet 保存，而不是作为临时客户端状态计算。

## 验证

产品构建、渲染-HTML 测试、lint 和依赖性审核作为最终验收的一部分运行。渲染的 HTML 套件显式检查 API 代币 field/header 和完整的可追踪链 shell。

TypeScript/TSX 诊断与 MVP 首先证明一种主要后端语言和框架的设计约束一致。它不被视为 UI 源已被语义扫描的证据。
