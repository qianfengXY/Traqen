# OpenClaw Workspace 分析验证 — 2026-07-22

## 目的

本报告使用真实的 [`openclaw/openclaw`](https://github.com/openclaw/openclaw) 仓库验证 Traqen 浏览器侧 Workspace 扫描器。验证以只读方式针对固定提交 `591c6ce3278d8c5011e5cad0fdef7381235f8f41` 进行，没有执行 OpenClaw 的安装、初始化、测试或运行命令。

## 范围与实际规模

固定 Git 树共包含 27,712 个文件，主要区域包括 `src`（11,622 个）、`extensions`（8,277 个）、`apps`（1,927 个）、`ui`（1,561 个）、`test`（792 个）和 `packages`（722 个）。完整的核心 `src` 树被检出并交给 Traqen 有界本地扫描器：

| 指标 | 结果 |
| --- | ---: |
| 提交给扫描器的核心 `src` 文件 | 11,622 |
| 支持并完成扫描 | 11,618 |
| 明确跳过 | 4 |
| 修正后提取的实现/API 候选 | 15,806 |
| 保守的确定性业务投影 | 265 |
| Gateway/RPC API 投影 | 329 |
| 已关联处理逻辑源码的 RPC 描述 | 304 |

被跳过的 4 个文件是 HTML/CSS 导出模板或 vendor 下的压缩 JavaScript。它们没有被静默计入“已分析源码”。

## 发现的问题与修正

原始基线把 15,715 个提取符号中的 11,630 个提升到了业务树。样例包含后端候选解析、任务记录构建、会话状态和测试支撑等内部辅助代码。这证明导出符号只是可定位的实现证据，不等于业务 Feature。确定性业务兜底规则现在更加保守，测试 helper/support 文件名变体也不会再产生 Feature 候选。修正后的 265 项仍然是等待模型对账的启发式候选，不是业务权威。

原始 API 投影为空，因为 OpenClaw 使用有类型的 Gateway/RPC 方法注册表，而不是 Express 风格路由。Traqen 现在会把 `GatewayMethodDescriptor`/`GatewayMethodSpec` 记录识别为 API 设计证据，其中包括方法名和授权范围；同时识别对应的 `GatewayRequestHandlers` 条目，并按精确方法标识关联实现代码。最终得到 329 个 RPC 接口，其中 304 个关联到具体处理逻辑源码。尚未关联的接口仍展示其描述器证据，不会错误绑定无关实现。

## 本次修改验证的模型失败处理

OpenAI-compatible 供应商即使声明支持 JSON mode，仍可能返回截断文本或不完整对象。Traqen 会继续二分无效批次。如果单候选原子单元仍没有完整有效的 JSON 对象或数组，现在会发出 `BATCH_SKIPPED`，保留确定性证据但不添加模型分类，把该单元记录为待处理并继续整轮运行。系统不会臆造缺失字段，也不会把它报告成成功的模型结论。

面向用户的 Agent 消息现在通过目标、动作、发现、证据、不确定性、检查点和下一步展示公开工作摘要。原始负载、请求标识、Token 诊断和有界预览仍放在“技术诊断”中；系统既不请求也不展示供应商或模型的私有思维过程。

## 剩余限制

- 本次运行验证了完整核心 `src` 树，不代表 27,712 个仓库路径中的每个源码文件都已扫描。
- 移动应用区域存在 Swift 和 Kotlin 源码，浏览器扫描器目前尚未支持。增加明确的语言适配器之前，Traqen 不能声称移动端覆盖完整。
- 确定性的 265 项业务视图只是高精度起始投影。用户可理解的产品能力需要独立的直接源码 Skill/模型分析并进行对账；扫描器结果本身不能成为业务真相。
- Gateway 描述器提取属于结构规则分析，不是 TypeScript 编译器证明。精确源码范围和处理器标识让结果可审计，但仍需要模型/Skill 复核与人工确认。
- 本次没有执行 OpenClaw，因此测试结果和部署运行证据仍为 `NOT_RUN`。

## 结论

真实仓库验证直接改变了产品行为，而不只是记录缺口：自定义 Gateway/RPC API 现在能展示设计与实现证据，测试支撑噪声被排除，确定性业务提升数量显著降低，模型 JSON 异常也不再中断 Workspace 分析。剩余缺口已被明确标为待处理，不会伪装成已完成分析。
