# ADR-0003：源码真相边界与下游准入

## 背景

F001 是存量系统分析的证据底座。没有明确源码边界时，一次扫描可能在可移动 branch、本地未提交目录或静默不完整的子集上完成；下游事实和语义主张表面可追溯，实际却指向可变或未知输入。

co-creator 已授权 2026-08-30 F001 收敛。本 ADR 记录源码凭据要被 F002–F004 使用所需的产品边界。

## 决策

1. Source Truth MVP 的每份快照只表示一个 Workspace 中一个已获只读授权的 Git 仓库和一个已解析的固定提交版本。
2. 声明范围默认整个已提交仓库，或一个可选目录根。MVP 不提供多目录根、glob/regex 规则或材料类别开关。
3. 采集只读且安全：不运行仓库提供的代码、hook、构建、依赖安装或不受信任 filter；对不可信边界或完整性条件安全关闭。
4. 声明范围内每个已发现条目都有一个明确处置。缺失、排除、脱敏、外部、不可读或失败材料持续可见，并可产生 `CoverageGap`。
5. 只有非阻断 Gap 可接受。接受记录责任人、理由和有效期；不删除 Gap，也不改变源码覆盖主张。身份、完整性、路径边界、策略和篡改失败均为阻断。
6. `SourceTruthReceipt` 分别表达身份、范围、完整性、覆盖、Gap 接受和一个可消费状态：`READY`、`READY_WITH_ACCEPTED_GAPS` 或 `BLOCKED`。
7. F002–F004 只消费 `READY` 或 `READY_WITH_ACCEPTED_GAPS` 的快照，并继承相关 Gap；拒绝直接文件系统路径、branch 名、脏工作区、未完成快照和阻断凭据。

## 被否决方案

### 实时本地目录或脏工作区来源

否决原因：其他 operator 无法重放其内容，本地编辑还可能在登记后静默改变分析证据。

### 任意范围规则或材料类型选择

否决原因：用户可在“扫描成功”的同时意外遗漏文档、配置、SQL 或测试。单一目录根是可理解边界；规则语言不是可信首期边界。

### 所有 Gap 阻断，或每个 Gap 都可接受

否决原因：全阻断会使常见遗留仓库无法使用；完全可接受会让完整性和权限失败退化为点击警告。仅非阻断 Gap 可接受，才能同时保持流动与真实。

### 用扫描成功或零 Gap 作为发布条件

否决原因：作业完成不能说明输入完整性；零 Gap 会诱导掩盖限制。分开的 Receipt 维度使限制可审计。

### 下游直接访问来源

否决原因：它绕过已固定的源码，并允许 F002–F004 从 Receipt 从未记账的材料中导出结果。

## 影响

- 产品用户只选择来源、授权、版本和可选目录根；平台策略拥有安全与完整性控制。
- 目录根凭据绝不能声称全仓库覆盖。
- 从快照导出的每条下游事实、候选、主张、执行结果或影响建议都保留非阻断 Gap。
- 将来支持本地密封文件集、归档、多仓库、多目录根或持续监听时，必须新建来源身份合同，不能作为未标记选项加入。

## 验证

- 对相同仓库 commit、范围和策略重放两次，验证相同来源身份和清单完整性结果；
- 验证 branch 移动不改变已密封快照；
- 验证范围内每项恰有一个处置，且不输出敏感原文；
- 验证已接受非阻断 Gap 对 F002 消费者仍可见；
- 验证路径逃逸、完整性失败或不可信来源身份持续为 `BLOCKED`，且不能变为可消费；以及
- 验证 F002 拒绝非合格 Receipt 的来源引用。
