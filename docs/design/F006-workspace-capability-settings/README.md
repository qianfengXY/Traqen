# F006 · Workspace 能力设置：功能与 UX 设计 V1.0

**一句话：先准备可信的全局资产，再为一个 Workspace 配好团队；草稿可以不完整，只有明确应用后的配置才供后续分析使用。**

本文是 2026-09-17 发布的功能与 UX 设计，不是代码完成声明。功能沿用已讨论的 F006 逻辑；视觉与交互按 co-creator 要求对齐 [F005 整体体验总纲 V2.1](../../design-reviews/F005/README.md)。F005 在其原线程仍是待评审提案，本次引用只确定 F006 的设计参照，不替其他 Feature 宣布采用。

阅读顺序：第 1–3 节看做什么，第 4–6 节看用户怎样完成任务，第 7–9 节看页面与恢复状态，第 10 节是独立效果图优化的交付合同。

效果图优化的待审阅读入口：[F006 桌面双主题效果图与交互原型 V1.0](ux-v1.0/README.md)。其中包含离线样稿、S01–S10 场景图、当前 main 的隔离 before 证据和 fixture 验证记录；它不改变本页的功能边界，不宣称生产实现完成，也不表示 operator 已批准。

## 1. 范围与本次发布依据

### 1.1 明确采用的产品边界

- F006 是配置中心，不自研 Agent Runtime；模型执行仍只经受支持的本地 CLI，API Key 和 OAuth 是认证方式，不是两种模型执行通道。
- 团队固定 **一个 Main、至少一个 Child**。新 Workspace 从一个未配置的 Child 开始，不强制两个 Child，也不静默使用默认模型。
- 全局资产、Workspace 可用范围、Agent 授权是三层不同的决定；“全局启用”不等于“所有 Agent 获得授权”。
- Workspace 本地 Skill 是独立资产，不是全局项的覆盖层，不允许借同名本地 manifest 修补或替换全局项。
- 不完整和失效配置允许保存为草稿。主动“应用配置”通过服务端校验后才产生不可变生效版本；运行不会热切换。
- **MCP 暂停本期设计实施与接线。** 本版只规定暂停状态的诚实呈现和历史记录处理，不选择 connector、不连接、不检测、不执行，也不把假执行器列为产品能力。
- 首次或配置变化后的分析确认，功能宿主是 **F003「分析准备」**，不是 F001 来源采集，也不是不依赖 Agent 的 F002。此处定义 F006 提供的摘要和交互边界，不宣称跨 Feature 的材料合同、启动 API 和持久确认机制已经落地。

## 2. 用户、范围与功能全景

主要用户是负责配置的管理员，以及要为本 Workspace 准备分析团队的授权成员。没有写权限的用户只能查看获准内容；服务端权限始终是依据，前端隐藏按钮不等于授权检查。

```text
全局设置                         Workspace 设置
账号 → CLI 模型 ──────────────→ Main / Child 选择模型
Skill 资产 ─────→ 可用能力范围 ─→ 每个 Agent 显式授权
                    ↑
              Workspace 本地 Skill
                              ↓
                         可恢复配置草稿
                              ↓ 用户主动应用
                       不可变生效配置版本
                              ↓ 后续真实消费者
                    F003 分析准备 → 固定版本运行

MCP：暂停；不进入本期可执行链路。
```

| 功能组 | 用户得到什么 | 主要操作 | 必须说明的边界 |
|---|---|---|---|
| 设置导航 | 清楚知道正在改全局还是某个 Workspace | 切换范围、选择 Workspace、返回业务页 | 切范围不是保存、Apply 或复制配置。 |
| 账号 | 可复用的认证引用与登录状态 | 新建、编辑、重新检查、停用或删除 | 不显示密钥，不在 Traqen 发起 CLI OAuth 登录。 |
| CLI 模型 | 经验证的执行选择 | 绑定账号、选择支持的 CLI、模型与参数、验证 | 无全局默认模型；验证成功不自动配给 Agent。 |
| Skill 资产 | 有服务端执行映射的能力目录 | 新建、选择已挂载执行器、查看验证状态、生命周期管理 | 自填“已验证”不能产生执行权限。 |
| Workspace 能力 | 当前 Workspace 的可用上限 | 禁用继承项、恢复继承、管理本地项 | 可用性不自动授权；全局停用不可本地复活。 |
| 团队 | 一个 Main 与完整的 Child 名单 | 选择模型、管理 Child、逐个勾选 Skill | 新 Child 不复制其他 Agent 的授权。 |
| 草稿与应用 | 不丢编辑，清楚知道何时生效 | 自动保存、处理冲突、应用、查看生效摘要 | 保存、验证、应用、运行是不同状态。 |
| 生命周期影响 | 改动前知道会影响谁 | 查看影响、确认停用/删除、修复失效授权 | 保留历史，绝不静默替换模型或能力。 |

有效范围计算仍是：`Workspace 可用能力 = 全局 active − 本 Workspace 禁用 + Workspace 本地能力`；实际执行还必须满足服务器就绪性与精确版本校验。`Agent 能力 = Workspace 可用能力 ∩ 显式授权`，不能只凭 ACTIVE 标签推导可执行。

## 3. 信息架构与对象状态

### 3.1 导航

顶层“设置”进入设置中心。页头始终显示“全局设置”或“Workspace 设置 · 订单平台”；范围切换使用带文字的选择器，不仅靠颜色和图标区分。

- 全局：**账号 / 模型 / Skill / MCP（已暂停）**。
- Workspace：**Agent 团队 / 能力管理**。从业务页进入时直接带入当前 Workspace，不再要求重选。
- “当前生效配置”是团队页的摘要与只读详情，不新增一套相互竞争的编辑入口。
- “查看使用位置”“查看版本详情”是对象的次级入口；不把执行器 digest、完整 revision ID、协议枚举铺在主页面。
- 原型的场景、主题与视口调试器放在产品壳外；不能混入真实业务导航。

### 3.2 四层状态不可合并

| 层次 | 用户用语示例 | 何时更新 | 不代表什么 |
|---|---|---|---|
| 本次编辑 | “正在保存…” / “保存失败，编辑仍保留” | 本地编辑与实际请求状态 | 不表示服务端已有此版本。 |
| 服务端草稿 | “草稿已保存 · 10:42” / “草稿有 2 项待处理” | 收到明确的保存回执 | 不表示已应用，不要求草稿有效。 |
| 当前生效配置 | “生效版本 8 · 今天 10:30” / “有未应用更改” | Apply 成功后读取服务端结果 | 不修改已运行任务，也不伪造连续版本号。显示号由服务端投影提供；不可用时显示时间与短标识。 |
| 某次运行使用配置 | “此运行使用生效版本 7” | Run 创建时固定 | 不随当前 Active 的版本 8 改变。 |

“可以应用”说明校验通过，不等于“已应用”。字段错误、账号不可用、执行器缺失、保存冲突都需要具体原因；不使用一个笼统的“异常”替代。

## 4. 全局资产的功能与 UX

### 4.1 账号

列表默认列为：名称、认证方式、适用 CLI/提供方、状态、最近检查；尾部为“重新检查”和更多菜单。首屏主动作“添加账号”。账户数量很少时也保留表头和空状态，不制造无意义统计卡。

编辑面板先选 **API Key / OAuth**：

- API Key 填 Secret 引用而非明文；当前支持的表单指引明确写 `env://VARIABLE_NAME`。引用不等于密钥值，UI 不回显解析结果。保存引用与连接验证分开，缺失环境变量的错误留在当前账号/模型，不丢表单。
- OAuth 展示受支持 CLI 的已登录状态和“重新检查”。说明“请在该 CLI 完成登录后回到这里检查”，不嵌网页登录、不读取私有 token、不自动改变用户的 CLI 配置。
- 对当前未支持的认证组合给原因，不生成看似可用的空账号。CLI 安装与登录状态来自服务端检查，不能按按钮点击次数改成成功。
- 修改或停用时先看影响；涉及其他 Workspace 的内容只能显示当前用户有权查看的摘要，不泄露名称、人员或秘密。

账号状态：未检查、检查中、可用、需要处理、已停用、已删除历史。颜色配文字；检查失败提供重试动作和非敏感原因。

### 4.2 CLI 模型

列表展示名称、CLI、模型标识、推理档位（适用时）、关联账号、就绪状态；名称是产品昵称，不能替代执行时真正的模型标识。

“添加模型”在同页侧面板完成：选择受支持的 CLI → 选兼容账号 → 填/选其模型与支持参数 → 保存 → 验证。不同 CLI 的字段按能力显示，不强行套用 Codex 参数。

- Codex 模型标识与推理档位必须能在确认摘要中看见，不能静默回退。
- 保存成功而验证失败显示“需要处理”，错误就在该行及仍打开的表单中；不得让用户以为创建按钮无响应。
- 模型在账号、CLI、模型 pin 或验证条件缺失时，不进入 Agent 的可选就绪项。已被选择而后来失效的模型保留可见并标原因，不能悄悄清空或替换。
- 不设置全局默认模型，不因添加成功自动 Apply 任一 Workspace；API Key 认证也不打开直接 API 模型执行。

### 4.3 Skill

列表展示名称、来源、绑定的服务端执行器、可用性；“添加 Skill”表单只提供实际挂载的执行器选项。能力名与说明可编辑，但运行映射及验证结果由服务器生成，不能输入签名冒充 VERIFIED。

空执行器目录时，明确“当前服务未提供可绑定的执行器”，禁止提交伪能力；历史未挂载项仍能查看，显示“需要处理”，不能新增授权或应用。全局项只有全局入口可改定义。

### 4.4 MCP 暂停界面

保留“MCP”导航以避免旧记录失踪，导航旁标“已暂停”。主区文案：“MCP 接入暂不推进。历史配置仅供查看，不代表当前可执行能力。”

目标界面不提供创建、导入、检测、激活或新增授权入口；有历史引用时展示受限只读清单和“到团队移除授权”。受限与不支持不是正在加载，更不能显示 READY 或绿色“已连接”。后端若仍接受旧 MCP Apply/新 Run，需单独修复并验证，不能以此视觉状态宣称准入已封闭。

## 5. Workspace 配置与应用

### 5.1 Agent 团队

页头先回答两个问题：“正在配置哪个 Workspace？”“哪些配置已经生效？”右侧保留唯一主动作 **应用配置**，旁边低强调展示自动保存状态。

团队总览按 Main、Child 1、Child 2…排列；Main 的统筹角色与 Child 的执行角色用文字解释，不用不同亮色制造等级竞争。卡片包含名称、角色、模型与档位、Skill 数量和局部就绪状态；MCP 暂停不计入“可执行能力”数量。

选中卡片在详情区编辑：模型选择 → Skill 授权 → 问题与修复入口。模型选择器展示账号状态和实际模型，不只显示昵称。未授权能力不可被 Agent 发现或调用；本设计不新增自由工具发现或自动分派授权。

- 初始状态：Main 和一个 Child 均待配置，提供“先准备模型”导航；不预设虚假 READY 团队。
- 添加 Child 不带默认模型和隐式能力；移除前解释其草稿配置将被删除，保留运行中的历史配置。至少一个 Child 的约束在 UI 和 Apply 校验均需表达。
- 已失效但仍被授权的能力继续显示为勾选、可撤销，并解释为什么不能应用；不要禁用整行，导致用户无法移除。
- 查看生效配置显示只读快照；返回草稿后保留此前的选中 Agent 和滚动位置，不用生效数据覆盖编辑。

### 5.2 能力管理

同页固定四组，组标题包含范围和数量：

1. **继承且可用**：全局启用、当前 Workspace 未禁用；可在本 Workspace 禁用。
2. **本 Workspace 已禁用**：可恢复继承；恢复只恢复可用范围，不自动给 Agent 授权。
3. **全局不可用**：停用、删除或缺失运行映射；可查看原因与影响，不能在此重新启用。
4. **Workspace 本地**：仅当前 Workspace 拥有，可新建、编辑、停用、删除，执行器同样必须服务端挂载。

组内按 Skill/MCP 类型标明；MCP 仅呈现暂停的历史项。搜索、空组提示和结果数保留，不将全部失效项默认过滤掉。添加本地 Skill 后仍需回到 Agent 显式勾选，创建不等于授权。

### 5.3 自动保存、Apply 与版本

编辑在后台按有界 debounce 串行保存。正常编辑不要求额外点“保存草稿”；因此不照抄参考效果图中的手动保存按钮。保存失败或冲突才出现相应恢复操作。

Apply 的前提是：存在草稿、当前编辑已经得到保存确认、无进行中的保存/冲突、模型及实际授权均通过服务端校验。空草稿显示“先完成团队配置”，按钮禁用并有可读原因，避免静默 no-op。

未被当前团队授权的失效目录项不阻断其他有效配置；校验针对实际选择和授权，不要求先修完全部全局资产。

点击后显示“正在应用…”，阻止重复提交。服务端只激活该次已验证的精确快照；成功回执明确新生效版本和“仅影响之后的新分析”。若收到失败，保留草稿和旧 Active，错误靠近 Apply。结果未知时先查询权威状态，不盲目重复创建版本。

切换范围或离开页面时，若仍有未确认写入或失败编辑，应明确提示并提供“留在此页处理 / 放弃未保存编辑并离开”；不能为了换页默认为保存成功。已持久化但未应用的草稿可以离开，回到同一 Workspace 时恢复。

### 5.4 两种 409 恢复

| 场景 | 页面响应 | 恢复后的正确结果 |
|---|---|---|
| 草稿版本冲突 | 保存停在一次失败，横幅说明另一处更新；Apply 禁用，保留本地编辑 | 用户明确选择“重试我的草稿”或“采用服务器草稿”，不后台无限重试。 |
| 选择重试，期间又有新编辑 | 读取当前服务器版本，只重存该次失败时冻结的编辑 M2 | 只确认实际保存的 M2。更晚 M3 仍是待保存，成功后恰好再保存一次；不能确认未送出的 M3。 |
| 选择服务器草稿 | 明示会丢弃尚未保存的本地修改；确认后取回服务器版本 | UI 与服务器一致、失败态清除；后续编辑可正常保存，旧“重试保存”不残留。 |
| 恢复请求再次冲突/失败 | 保留输入并显示新错误 | 不假装已恢复，不自动改选另一个恢复策略。 |

409 横幅存在时继续编辑 M3，不得触发新的自动 PUT；禁用 Apply 还必须意味着零 activation 请求。错误恢复以后再判断是否可应用，不通过颜色变化冒充保存确认。

### 5.5 能力停用与删除的影响确认

从目标能力行操作 → 请求当前影响 → 展示受影响 Workspace/Agent 与当前对象 → 输入该能力名称确认 → 服务端校验并执行。不能用通用“确认”二字替代能力名称。影响加载失败时不可用空列表代替；影响发生变化时更新并重新确认。

完成后全局目录显示真实生命周期，受影响团队变为“需要处理”，失效授权仍可撤销；旧 revision 和运行历史不变。取消对话框不产生写入。焦点返回原操作行，行消失时落到相邻可操作对象。

## 6. F003 分析准备中的 F006 摘要

用户真正启动 Agent 调查前，F003 展示服务端已生效配置的 Main/各 Child 模型、能力数量、账号就绪性和非敏感版本标识；无 Active 或就绪性失败时给“前往设置修复”，不能隐式应用草稿。

首次或生效版本变化要求确认；同版本免重复提示也不能跳过当前权限、材料准入和能力检查。若确认后 Active 变化，服务端返回对应配置 Head 的冲突：保留调查输入、刷新摘要、重新确认，不自动换版本重发。其他 409 不能都解释成配置变更。

原 Run 的来源、参考数据集和配置版本固定；刷新、暂停恢复和重试不改用当前 Active。未知创建结果先查询或按既定幂等合同恢复，不能盲目另建 Run。

**交付限制：** 确认按何种主体去重、何时持久化消费、材料绑定与原子建 Run 合同仍需联合确定。本版只画明确标识的交互示意，不发明 API 字段，不重新开放接收实时目录的旧分析入口，不用原型点击成功证明 AC-C2 已实现。

## 7. 对齐 F005 的桌面布局与视觉语言

### 7.1 设备、主题与空间

本期是桌面设计，**不再以 375px 旅程作为新 UX 的主验收**。保留旧移动证据不等于新增移动承诺。

| 约束 | 14 英寸笔记本 | 27 英寸显示器 |
|---|---|---|
| 主设计视口（CSS px） | 1440 × 900 | 2560 × 1440 |
| 附加布局检查 | 1280 × 800 | 1920 × 1080 |
| 主导航宽度 | 224 | 244 |
| 内容外边距 | 34 | 横向 48、纵向 42 |
| 团队编辑布局 | 总览与详情两区；优先确保详情可读，空间不足时同区切换详情并可返回团队 | 总览与详情并列、阅读宽度受限；增加可见内容，不按比例放大字号 |
| 表单 / 说明 | 表单建议最大 720；说明正文避免长行 | 同样限宽，多余空间用于对照摘要，不把输入框拉满屏 |

“14/27 英寸”是使用场景，不是像素换算。保留操作系统缩放、200%/400% 浏览器缩放下的可达性；必要时顺序重排，不裁掉主操作或强迫横向拖动才能读错误。

默认 **瓷白**，可切 **石墨**；采用稳定 themeId 与 token 映射，保留未来主题扩展。主题偏好持久化；切换时不清草稿、选中 Agent、滚动、范围或错误状态。原型存储须与产品数据隔离。

### 7.2 视觉规范

F005 是 token 和组件规范的来源；下面是本版用到的映射摘要，不另建一套相似但不同的主题。

整体为清晰、克制的专业工具：白/灰或石墨分层、低阴影、少装饰。重要状态不依赖大面积绿色条；不在阅读区铺玻璃模糊或渐变，不放 macOS 窗口交通灯、品牌标志或假系统控件。

### 7.3 团队页的阅读顺序


设置次级导航采用稳定的一层；范围切换器、导航、团队卡片各自承担不同任务，不能堆成三套同样醒目的 tabs。只有一个当前选中状态，不把“可用”“选中”“已应用”都画成蓝色实心。

## 8. 状态、文案与无障碍

| 状态 | 必须能看见 | 可操作恢复 |
|---|---|---|
| 无账号/模型/执行器 | 原因与下一步，不放假数据填满布局 | 去对应资产页；保留返回 Workspace 的上下文 |
| 加载 / 检查中 | 真实进度状态、操作范围 | 可取消时给取消；不能冒出成功 toast |
| 账号/模型验证失败 | 对象名称、非敏感原因、检查时间 | 原位重试或修正字段，保留输入 |
| 草稿无效 | 问题数量与跳到相应 Agent/字段的入口 | 仍允许保存，不允许 Apply |
| 保存失败 / 409 | 当前编辑仍在、服务端是否确认未知或冲突 | 对应重试 / 采用服务器草稿；不互相替代 |
| Apply 失败 | 旧生效版本未变、具体待处理项 | 修复后主动再应用，不自动重试 |
| 全局失效 | 哪个授权已不可用、原因与来源 | 可撤销授权；不能禁用整行封死修复 |
| MCP 暂停 | 明确暂停，不是正在准备 | 历史只读、移除旧授权；无连接操作 |

产品文案用中文任务词，如“草稿已保存”“需要处理”“应用配置”。协议错误保留在可展开详情中，主文案先解释原因与行动；开发者字段不能直接挤成用户的英文错误墙。错误不得包含 secret 值或认证响应原文。

字段有常驻 label 与关联错误说明；键盘可遍历范围、导航、卡片、表单、授权和对话框。状态变化使用适当的 live region，错误以 `role=alert` 通知但不重复轰炸；保存状态不抢焦点。弹窗关闭恢复焦点，异步校验不打断正在输入的字段。遵守减少动画偏好；对比度按 F005 的 WCAG 2.2 AA 目标逐状态验证，不把 token 表当作已经通过无障碍测试。

```yaml
in_context_observability:
  primary_surface: "设置中心的对象行、选中 Agent 详情和 Apply 附近的状态区"
  why_here: "用户正在修改和修复这些对象，无需跳到独立状态仪表盘"
  status_projection: "就绪、保存、冲突、应用分别由其权威结果投影"
  deep_dive: "查看影响、非敏感诊断与只读版本详情"
  noise_dedup: "一次失败一个稳定提示；编辑恢复后清理旧错误；相同后台状态不重复 toast"
```
