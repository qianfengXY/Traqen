# Traqen 网页

Traqen 的证据优先 Feature 可追溯模型的产品表面。

默认屏幕把 Traqen 仓库本身作为首个 `SELF WORKSPACE`。功能追溯能力直接展示仓库内真实的设计文档、领域源码、环境配置契约、测试设计和执行结果；`trace-chain.js` 变化场景用于说明为什么只有实现派生层会过期。连接面板可以从运行中的 Traqen API 加载同一份服务端派生投影；浏览器不会重新计算替代可信分数。

## 产品表面

- Feature具有独立权威、一致性、验证、新鲜度、冲突维度的可追溯性。
- 左侧 Workspace 切换器可以保留多个本地项目。第一次扫描用于初始化项目；后续扫描同一根目录时复用路径、大小、最后修改时间和扫描器版本均未变化的记录，只重新读取新增或修改文件；扫描器升级后旧记录自动失效。IndexedDB 仅保存文件元数据、派生功能索引、有界代码/测试片段和脱敏配置，不保存完整原始源码。“功能追溯”和“追溯图谱”均使用当前项目的功能树与当前功能。
- Workspace 分析是分层统计看板，不再重复功能追溯详情。它可以针对整个项目或功能树任意选中节点，统计功能点、设计实现、配置、测试、执行结果、待人工确认、证据链完整度、TraceGap、冲突和明确不符合；未知与待审核状态不会被误算为不符合。
- 五段式“功能描述 → 设计实现 → 配置 → 测试用例 → 测试结果”视图。功能说明和测试策略分别使用一个连续文档框，不再由多个嵌套卡片组成。设计实现读取仓库中对应的 Markdown 设计文件，并可在渲染后的设计文档、原始 Markdown、业务代码块和完整原始源文件之间切换。配置对比 DEV/SIT/UAT/PROD；测试用例包含可展开的版本化条目；测试结果按场景组织，失败执行可下钻到对应用例、失败步骤、期望/实际值、错误和 Evidence。
- 参考 Apple 显示风格并针对 27 英寸桌面优化的视觉系统，使用更大的系统字体、克制的色彩、舒适的阅读宽度，并统一功能追溯、图谱、审核、影响和指标页面的布局。
- 全局“中文 / English”按钮统一控制导航、页面文案，以及类型、状态、角色、关系、策略值和测试结果的共享词典。ID、API 值、配置键和源码保持规范原值；设计阅读器会选择对应的中文或英文 Markdown 文件。
- 预留未来 Agent 契约：Agent 消费已批准的不可变 TestSpec 版本，回传结构化步骤/断言结果、签名 Evidence 和 Runner 身份。本阶段不接入外部 Agent 执行，Agent 也不能改写业务权威或自行决定最终可信状态。
- 可见的 TraceGap 所有权以及阻止功能显示为完整的原因。
- 语句级审核，加载真实的反向运行候选者并提交经过身份验证、服务器验证的 Decision，而不接受客户端提供的审核者身份。
- 历史 Snapshot 比较由不可变的 ChangeSet API 支持，包括保留的规范事实、无效的派生层和修复队列。
- 授权实施修复，将新的 Snapshot 反向候选链接回现有 Claim 并仅恢复实施一致性段。

## 本地开发

需要 Node.js 22.13 或更高版本。

在仓库根目录首次安装依赖，然后使用统一命令同时启动 Web 应用和本地 API：

```bash
npm run setup
npm run dev
```

打开 `http://127.0.0.1:3000` 即可访问页面。API 已在 `http://127.0.0.1:3100` 启动，与产品中的默认连接地址一致。按下 `Ctrl+C` 会同时停止两个进程。

如需单独开发 Web 包，可运行：

```bash
cd web
npm run dev
npm test
```

单独部署 Web 时，仍必须在 `CORS_ALLOWED_ORIGINS` 中明确列出其来源；通配符来源会被拒绝。

## 信任边界

演示审核按钮从不坚持商业真理，并进行相应的标记。加载真正的候选者后，正式审核需要一个不记名令牌，该令牌保留在页面内存中，并在成功后被清除；审阅者身份和角色仍然仅来自服务器。 TestSpec 批准、跟踪重新计算和 Evidence 摄取仍然是服务器授权的工作流程。 UI 使用服务器派生的 Feature 可追溯性和 ChangeSet 合约，而不是从客户端数据推断完整性或影响。
